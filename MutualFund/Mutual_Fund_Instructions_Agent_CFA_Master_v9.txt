4.0 CENTRAL DECISION ROUTER (run this before any section-specific logic)
------------------------------------------------------
PURPOSE: Single IF-ELSE classifier that resolves all scope overlaps
and routes every decision to the correct execution path. An LLM
must pass every decision through this router before applying any
section-specific rule. This prevents scope confusion and hallucination.

DECISION ROUTER (apply in exact top-to-bottom order; stop at first match):

  STEP 1 — Check immediate triggers T1/T2/T3:
    IF any of T1, T2, T3 fires:
      → EXECUTE IMMEDIATELY (Priority 1)
      → Exempt from churn limit
      → All other analysis continues but does not block T1/T2/T3

  STEP 2 — Check regime:
    IF current regime = BEAR:
      → BLOCK all fund switches and SIP changes
      → PERMIT only: buffer updates, logging, monitoring state changes,
        audit summary writing (see exhaustive list in Section 4.1)
      → Run delta filter in EVALUATION-ONLY mode (no execution)
      → Continue to Steps 3–7 for diagnostic purposes only

  STEP 3 — Check T12-A:
    IF XIRR in WEAK/EROSION for 2 consecutive reviews AND no T12-B yet:
      → LOG ONLY (T12-A fires)
      → Produce written audit summary
      → Does NOT break NO ACTION. Does NOT use churn slot.

  STEP 4 — Check T12-B:
    IF T12-A audit found an actionable issue:
      → EXECUTE permitted actions per regime
      → In Bear: buffer/logging only
      → In Bull/Flat: may include allocation rebalance (SIP amounts)
      → Counts toward churn limit (if fund change)

  STEP 5 — Check Core fund downgrade (Priority 2):
    IF a Core fund meets all 3 structural weakness conditions (5.6 Tier 2):
      → Reclassify to Satellite
      → Run delta filter (standard or elevated mode per regime)
      → If delta clears: PERMIT switch (counts as 1 churn)

  STEP 6 — Check review-period triggers T4–T11 (Priority 3):
    IF any T4–T11 fires AND regime is Bull or Flat:
      → EXECUTE per trigger rules
      → Apply churn limit

  STEP 7 — Check delta filter (Priority 4):
    IF regime is Bull or Flat AND churn slots remain:
      → Run delta filter on any candidate improvement
      → IF all 3 deltas + cost gate clear: PERMIT switch
      → IF any delta fails: → GO TO STEP 8

  STEP 8 — Check NO ACTION:
    IF no steps above produced an execution:
      → Check Hard NO ACTION conditions (a–i in Section 4.5)
      → IF all confirmed: declare HARD NO ACTION
      → IF some deferred (data unavailable): declare SOFT NO ACTION
      → In either case: produce mandatory 5-line output (Section 4.5)
      → STOP. Do not add commentary beyond the 5 lines.

4.1 MASTER DECISION HIERARCHY (apply in this strict order)
------------------------------------------------------
RULE: Every decision flows through this hierarchy top-to-bottom.
The hierarchy has two distinct scopes — this distinction is
critical for logical consistency:

  FUND SELECTION SCOPE: governs whether to switch, add, or
    remove a fund. Regime is the primary constraint here.

  RISK & SAFETY SCOPE: governs structural audits, buffer
    mandates, and capital preservation actions. Certain triggers
    (T1/T2/T3/T12/ST2) operate in this scope and can supersede
    regime rules because they protect capital, not select funds.

LAYER A — HARD TRIGGERS (Section 7.1)
  Scope: BOTH — applies to fund selection AND risk/safety.
  Regime-independent. Always checked first.
  Immediate triggers T1/T2/T3 fire regardless of regime.
  Review triggers T4–T11 are regime-gated (Bull/Flat only).
  T12 (XIRR structural audit) fires regardless of regime —
    this is a RISK/SAFETY trigger, not a fund selection trigger.

LAYER B — REGIME RULES (Section 4.2)
  Scope: FUND SELECTION only.
  Regime determines which screening rules are active, which
  fund-switch decisions are permitted, and what delta thresholds
  to use. Regime governs fund selection decisions only.
  Regime does NOT prevent risk and safety actions such as:
    - T12 structural audit (fires in any regime)
    - ST2 buffer mandate (fires in any regime)
    - T1/T2/T3 immediate triggers (fire in any regime)

LAYER C — XIRR ZONES (Section 8.1)
  Scope: DIAGNOSTIC only (does not execute fund switches).
  XIRR zones do NOT override regime for execution decisions.
  XIRR zones CAN independently trigger structural review flags
    regardless of regime (via T12 — see XIRR/Regime Rule below).
  Distinction: a structural review flag is not a fund switch.
  It is an audit instruction. The audit may conclude "no action."

LAYER D — DELTA FILTER (Section 7.2)
  Scope: FUND SELECTION only.
  Applied last. Cannot override Layers A, B, or C.
  In Bear regime: evaluation-only mode (no switch executed).
  In Bull/Flat: can permit (not mandate) a switch.

VISUAL SUMMARY:
  [FUND SELECTION PATH]
  Hard Triggers (A) → Regime Rules (B) → XIRR Diagnostic (C) → Delta Filter (D)

  [RISK & SAFETY PATH — supersedes regime for non-selection actions]
  T1/T2/T3 (immediate) | T12 (XIRR audit) | ST2 (buffer) → Execute regardless

XIRR / REGIME INTERACTION RULE (resolves apparent conflict):
  XIRR does NOT override regime for EXECUTION decisions.
    → In Bear regime, a WEAK XIRR zone does not permit fund switches.
    → This rule is absolute for fund selection decisions.
  XIRR CAN trigger structural review flags independent of regime.
    → Two consecutive WEAK/EROSION reviews → T12 fires in any regime.
    → T12 outcome is a structural AUDIT, not a fund switch.
    → T12 in Bear → audit is READ and LOGGED only. All execution
      decisions from the audit are DEFERRED to next review.
  Summary: regime gates execution; safety triggers gate survival.

EXHAUSTIVE PERMITTED vs PROHIBITED IN BEAR REGIME:
  PERMITTED (from any risk/safety trigger — T12, ST2, RRM):
    Buffer status update (FUNDED/PARTIAL/UNFUNDED)
    Log findings in Portfolio Health Log + Core Warning Log
    Monitoring state change (NORMAL → AT RISK → flag only)
    Earlier review scheduling
    Risk Rebalancing Mode documentation (write, do not execute)
    Structural audit summary (write findings, defer all actions)
  PROHIBITED in Bear regardless of trigger source:
    Fund switch or removal (Core or Satellite)
    SIP amount changes (increase or decrease)
    Allocation rebalancing via SIP adjustment
    Adding new fund positions
    Treating 'structural rebalance' as a permitted SIP change

4.5 NO ACTION STATE (mandatory output when nothing triggers)
------------------------------------------------------
PURPOSE: When all checks pass and no trigger, drift, or zone
fires, the system must produce a defined "NO ACTION" output.
Without this, LLMs fill silence with invented observations or
spurious recommendations.

NO ACTION comes in two variants. Use HARD NO ACTION when all
data is available. Use SOFT NO ACTION when data gaps exist
but no execution is warranted.

HARD NO ACTION — all 9 conditions confirmed:
  (a) All T1–T12-B triggers: not fired
      (T12-A may have fired — audit scheduled is OK for HARD NO ACTION)
  (b) All allocation categories: within ±5% drift band
  (c) XIRR zone: TARGET or HEALTHY (or WEAK first occurrence, T12-B not due)
  (d) All overlap pairs: within tier thresholds
  (e) All correlation pairs: within threshold or unavailable (Rung 4 OK)
  (f) All 3 stress tests passed; Risk Rebalancing Mode: INACTIVE
  (g) No Core fund in AT RISK or DOWNGRADED state
  (h) Buffer: FUNDED or PARTIAL
  (i) Churn count: 0 of 2 used this period

SOFT NO ACTION — one or more data points missing/stale, but no
execution is warranted based on available data:
  Conditions: (a) through (i) above must either PASS or be DEFERRED
  due to data unavailability (not FAILED).
  At least (a), (b), and (f) must be confirmed (non-deferrable checks).
  All other conditions may be deferred with explicit notation.
  Output: produce SOFT NO ACTION with DEFERRED items listed.
  No fund change, SIP change, or allocation rebalance is permitted
  in Soft NO ACTION state regardless of deferred items.

MANDATORY NO ACTION OUTPUT (all 5 lines required):

  LINE 1 — STATUS DECLARATION:
    "NO ACTION REQUIRED. All checks passed at [Review Date]."

  LINE 2 — CHECKS COMPLETED (list all that were run):
    "Completed: T1–T12 trigger check | Allocation drift |
    XIRR zone | Overlap matrix | Correlation | Stress tests |
    Core fund status | Buffer status"

  LINE 3 — XIRR CONFIRMATION:
    "Portfolio XIRR: [X%] | Zone: [TARGET/HEALTHY] |
    Data freshness: confirmed within 7 trading days."

  LINE 4 — NEXT REVIEW:
    "Next scheduled review: [Date]. No early review required."

  LINE 5 — HOLD INSTRUCTION:
    "All 8 SIPs continue unchanged. No fund additions,
    removals, or SIP amount changes are recommended."

CRITICAL RULES FOR NO ACTION STATE:
  - Do NOT add commentary, observations, or "areas to watch"
    beyond what is defined above. Invented commentary signals
    that the LLM is padding output. Resist this.
  - Do NOT suggest "minor improvements" or "worth monitoring
    over the next few months" — if it doesn't trigger a rule,
    it does not belong in a NO ACTION output.
  - Do NOT produce a NO ACTION declaration if ANY single check
    condition (a through i) is not fully confirmed. If even
    one is uncertain due to stale data or unavailable source,
    state the specific uncertainty and defer that check.
  - A NO ACTION declaration is a complete, professional output.
    It is not a failure to find something. It is the correct
    result when a well-constructed portfolio is on track.

PARTIAL NO ACTION (some checks clear, one deferred):
  If one condition cannot be confirmed (e.g., XIRR data stale):
  → Declare NO ACTION for all confirmed checks
  → Flag the deferred check explicitly:
    "DEFERRED: XIRR zone check — NAV data stale as of review
    date. Re-confirm within 7 trading days and append result."
  → Do not treat deferral as a trigger or reason to recommend
    any fund change.

5.2 TOP QUARTILE DEFINITION (complete, with fund age handling)
------------------------------------------------------
STANDARD DEFINITION (fund age >= 3 years):
  Top Quartile = fund's 3Y rolling CALENDAR-YEAR returns
  (Jan–Dec, full year periods) place it in the top 25th
  percentile of its DIRECT PLAN category peer group.

  UNIVERSE RULE: Direct Plans vs Direct Plans ONLY.
  Regular Plans are excluded entirely — their ~0.5–1.0% lower
  returns (due to distributor commission) would inflate apparent
  rank if mixed in.

  DATASET VERSION: Use 3Y rolling calendar-year periods, NOT
  trailing 1Y or arbitrary 3Y from today. This reduces
  recency bias and gives a more stable percentile rank.

  Source: Value Research (apply "Direct" plan filter explicitly
  before reading any rank). INDmoney (confirm Direct view active).
  Re-verify at every review — never rely on stored data. Powerup oe Economic Times

FUND AGE < 3 YEARS (incomplete history rule):
  If a fund has less than 3 years of return history:
  (a) Use inception-to-date (ITD) percentile rank within
      the Direct plan peer group for the same period.
  (b) Minimum viable history: 1 year. Below 1 year → do not
      evaluate for Top Quartile — insufficient data.
  (c) Flag clearly in all output: "INCOMPLETE HISTORY — ITD
      PERCENTILE USED. 3Y RANK UNAVAILABLE."
  (d) Do NOT treat an ITD top-quartile result as equivalent
      to a 3Y top-quartile result. It is a provisional signal
      only. Apply a higher delta threshold (+0.5% on Alpha)
      when comparing against a fund with full 3Y history.
  (e) Recheck at every review until 3Y history is available.

5.6 CORE FUND TWO-TIER WARNING SYSTEM
------------------------------------------------------
Core funds are protected against casual switching but NOT
immune to structural decay. Two-tier warning system:

THREE CONDITIONS TO MONITOR:
  Condition A: Fund drops out of top quartile (Direct peer group,
               3Y rolling) — sustained, not a single dip
  Condition B: Underperforms category benchmark on 3Y rolling
               basis for 18+ consecutive months
  Condition C: Alpha falls below 3.0 or turns negative for
               2 consecutive 6-month review periods

TIER 1 — AT RISK CORE (2 of 3 conditions met):
  - Flag the fund as "AT RISK CORE" in review output
  - Do NOT switch or reclassify yet
  - Increase monitoring frequency: note in every subsequent review
  - Run delta filter in evaluation-only mode on top alternatives
    to have a replacement candidate ready
  - State: "Core fund [name] is AT RISK CORE. [A/B/C conditions
    met: list them]. No action yet. Monitoring."

TIER 2 — DOWNGRADE TO SATELLITE (all 3 conditions met):
  - Reclassify fund from Core to Satellite
  - Apply full delta filter against best category alternative
  - If delta filter clears → switch is permitted (not mandatory)
  - Apply churn limit (Section 6.2) — counts as 1 of 2 changes
  - State: "Core fund [name] downgraded to Satellite. All 3
    structural weakness conditions met. Delta filter applied."

RESET: If a condition clears at a subsequent review (fund re-enters
top quartile, or alpha recovers), remove the relevant flag.
A fund that was AT RISK CORE reverts to normal Core status
if it clears the condition that triggered the warning.

6.1 ALLOCATION DRIFT CONTROL
------------------------------------------------------
Drift > ±5% from target allocation → SIP REBALANCE ONLY.
Never redeem units to fix drift. Never confuse drift with
a fund change trigger — they are completely separate.

+---------------------+---------+-------------------+----------------------+
| Category            | Target  | Trigger Range     | SIP Action           |

7.2 DELTA FILTER
------------------------------------------------------
BULL/FLAT REGIMES — STANDARD MODE:
A switch is PERMITTED (not mandatory) if ALL THREE deltas
AND the final cost gate are cleared.

BEAR REGIME — EVALUATION-ONLY MODE:
Delta filter runs but no switches are executed.
Purpose: identify and document replacement candidates so that
when the regime transitions to Flat or Bull, candidates can be
evaluated fresh. Record in Deferred Changes Log.

STATELESS EXECUTION RULE (critical):
  Evaluation-only outputs from Bear regime are REFERENCE DATA,
  not pre-decisions. They must NOT carry forward as actionable
  recommendations across sessions.
  At each new session, the LLM must re-run the delta filter
  from scratch using current data — not inherit Bear-era
  candidates as already-approved switches.
  The Deferred Changes Log is a memory aid for the investor,
  not a pre-authorised action queue.
  An LLM loading this file must re-evaluate all deferred items
  against the current regime, current fund data, and current
  delta thresholds before any switch is permitted.

DELTA 1 — Alpha improvement:
  Bull : Candidate Alpha (3Y) > Current by >= 1.5% CAGR
  Flat : >= 2.0% CAGR (higher bar — ratios distorted)
  Bear : Evaluate and flag; no switch executed

  INCOMPLETE HISTORY ADJUSTMENT: Add +0.5% when replacement
  candidate has < 3Y history (ITD percentile used).
  DELTA INFLATION CAP: Maximum +1.0% above the base threshold.
  Example: Bull base = 1.5%. With incomplete history: 1.5+0.5=2.0%.
  Cap applies: even if multiple adjustments stack, threshold
  cannot exceed base + 1.0%.
  Bull max: 2.5% | Flat max: 3.0% (base 2.0% + cap 1.0%)

DELTA 2 — Risk-adjusted improvement (at least ONE):
  Bull : Sharpe >= +0.20 OR Sortino >= +0.30 (3Y)
  Flat : Sharpe >= +0.25 OR Sortino >= +0.35 (3Y)
  Bear : Evaluate and flag; no switch executed

DELTA 3 — Cost neutrality:
  Replacement ER <= current fund ER
  If higher ER: Alpha improvement must exceed 2.5% to compensate

INCOMPLETE HISTORY ADJUSTMENT:
  Defined within Delta 1 above. Cap applies (see Delta 1).
  Example: In Bull, threshold becomes 2.0% instead of 1.5%.

FINAL COST GATE (mandatory — apply in all non-Bear regimes):
  Step 1 — Tax: Check purchase date of each lot.
    Units < 1 year: STCG = 20% of gains on those lots.
    Units > 1 year: LTCG = 12.5% on gains above Rs 1.25L/year.
  Step 2 — Exit load: Check AMC website (Tier 1).
    Typically 1% if < 1 year; nil if > 1 year. Verify per fund.
  Step 3 — Compounding restart cost [SOFT FACTOR — non-binding]:
    This is a speculative estimate. 30–60 day SIP gap at
    Rs 50,000/month and 15% XIRR: approx Rs 3,000–5,500.
    Label: SOFT. Include in net benefit calculation as reference.
    Do NOT use this estimate alone to block a switch that clears
    Deltas 1, 2, and 3. It is an adjustment, not a veto.
    If Steps 1+2 (hard costs: tax + exit load) already exceed
    the net benefit threshold, Step 3 is irrelevant.
  Step 4 — 3-year gain from replacement:
    Expected Alpha improvement (%) × SIP amount × 36 months.
  Step 5 — Net benefit = Step 4 − (Step 1 + Step 2 + Step 3)

  SCALED THRESHOLD: Net benefit must exceed:
    max(Rs 15,000, 0.5% of current portfolio corpus)
    At Rs 20.5L corpus: max(15,000, 10,250) = Rs 15,000
    At Rs 40L corpus:   max(15,000, 20,000) = Rs 20,000
    At Rs 60L corpus:   max(15,000, 30,000) = Rs 30,000
  If net benefit < threshold → DO NOT SWITCH.
  If net benefit >= threshold → switch is financially justified.

BEHAVIORAL RULE:
  Default mode: HOLD + MONITOR.
  Optimization Mode (all delta thresholds reduced 20%):
  Activated only by explicit investor request per session.
  Example: "Run optimization mode for this review."
